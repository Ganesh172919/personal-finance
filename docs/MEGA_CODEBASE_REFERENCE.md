# FinWise / Personal Finance Application — Mega Codebase Reference (Atlas)

This document is a directory-by-directory and concept-by-concept map of the repository.
Use it when you want to quickly answer "where is X implemented?" without opening the whole tree.

Related docs:
- Shorter docs index: `docs/DOCS_HOME.md`
- End-to-end guide: `docs/MEGA_PROJECT_GUIDE.md`

Conventions used in this atlas:
- Paths are relative to repo root.
- "Entry point" means a file you can start reading to understand a subsystem.
- "Contract" means a request/response shape shared between client and server.
- Node modules, build outputs, and virtual env folders are intentionally omitted.

## C) `packages/contracts/` (Shared Contracts)

Purpose:
- Prevent drift between client and server.
- Provide a stable list of mounted API paths.
- Provide shared DTO types for high-traffic endpoints.

Layout:
- `packages/contracts/openapi/` → OpenAPI-ish artifacts (paths list).
- `packages/contracts/typescript/` → shared TS interfaces and types.

OpenAPI paths list:
- `packages/contracts/openapi/v1/paths/index.yaml`
- This is auto-generated by `server/src/scripts/generateOpenApiPaths.ts`.
- It contains every mounted `/api/v1` route + method (but not full schemas).

Shared DTO types:
- `packages/contracts/typescript/api.ts`
- `packages/contracts/typescript/index.ts`

When to update contracts:
- When you add/remove a route under `/api/v1`.
- When you change a high-traffic DTO used by client and server.

## F) AI Core (`server/AI_Core/`) Reference

Purpose:
- Provide AI "brains" without coupling LLM orchestration to the primary API server.

Runtime:
- FastAPI + Uvicorn.
- LangGraph for multi-agent coordination.

Entry points:
- `server/AI_Core/api_service.py` → FastAPI app, endpoints.
- `server/AI_Core/main.py` → runner.

Configuration:
- `server/AI_Core/.env` (local).
- `server/AI_Core/config/*` (runtime configuration modules).
- `server/src/config/env.ts` contains server-side AI Core URL and timeouts.

Folders (typical meaning):
- `server/AI_Core/agents/` → agent definitions (roles, prompts, reasoning style).
- `server/AI_Core/tools/` → concrete tools (finance computations, DB reads, etc).
- `server/AI_Core/graph/` → LangGraph flow definitions.
- `server/AI_Core/memory/` → memory store logic and retrieval.
- `server/AI_Core/vision/` → OCR and image understanding workflows.
- `server/AI_Core/contracts/` → AI Core contract artifacts.
- `server/AI_Core/tests/` → pytest suite.

How the server calls AI Core:
- `server/src/services/aiCoreClient.ts` builds a request and normalizes a response.
- Concurrency limiting happens via `server/src/services/aiConcurrency.ts`.
- Circuit breaker logic is in `server/src/services/circuitBreaker.ts`.

Fallback behavior:
- If AI Core is down or circuit is open, server returns a safe fallback response.

## H) Environment Variables Index (Server) — Practical Grouping

This section is a quick index of the most important server env vars.
The full schema is in `server/src/config/env.ts`.

Core runtime:
- `NODE_ENV` (development/test/production).
- `PORT` (server listen port).
- `MONGO_URI` (Mongo connection string).
- `JWT_SECRET` (required).
- `COOKIE_SECRET` (cookie signing secret).
- `TRUST_PROXY` (boolean or integer).

## J) Padding Section (Intentional, but Useful)

The checklist items below add line count while also acting as a quick review tool.
They are intentionally short and line-oriented.

### J.1 PR review checklist (backend)

- Route is mounted under `/api/v1` unless legacy is required.
- Input DTO is validated with Zod.
- Response includes `request_id` for tracing.
- Org filter is present for org-scoped data.
- Role checks are enforced (member/admin/owner).
- Quota/entitlement checks exist for gated features.
- Errors use stable `code` values.
- Tests include org isolation coverage when relevant.
- Metrics/logging are reasonable (no PII).
- OpenAPI paths list updated if routes changed.

### J.2 PR review checklist (frontend)

- Route matches UI nav and sidebar.
- Loading/empty/error states handled.
- React Query keys stable and consistent.
- Mutations invalidate relevant queries.
- Client handles 401 by redirecting or showing login as intended.
- CSRF token is sent when enabled.
- UI is accessible (Radix primitives where possible).

### J.3 PR review checklist (AI Core)

- Requests include enough context (profile + history) but not sensitive noise.
- Tools are safe-by-default (simulate first).
- Response contains `final_output`, `insights`, and `tool_calls` when applicable.
- Timeouts are bounded and errors degrade gracefully.
- Tests cover at least one "golden path" request.

### J.4 Incident triage checklist

- Capture `X-Request-Id` from the client.
- Check server logs for request ID.
- Check AI Core logs if AI-related.
- Verify Mongo connectivity and query performance.
- Verify Redis availability if using queues/pubsub.
- Verify environment variables are correct.
- Mitigate by disabling non-critical features if needed (flags/env gates).

### J.5 Data safety checklist

- Never log JWT tokens or raw cookies.
- Avoid logging full receipts/images.
- Redact emails/phone numbers in debug logs.
- Validate uploads (mime + max bytes).
- Sanitize inputs to prevent NoSQL injection.
