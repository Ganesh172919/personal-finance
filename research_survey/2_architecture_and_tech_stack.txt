SURVEY PART 2: TECHNICAL ARCHITECTURE AND TECHNOLOGY STACK

1. High-Level Architecture
The repository follows a modular multi-service layout:
- `client/`: React + Vite single-page application
- `server/`: Express + TypeScript API and business logic
- `server/AI_Core/`: FastAPI + LangGraph AI service
- `packages/contracts/`: shared OpenAPI contract assets
- `docs/`: implementation and operational documentation

2. Frontend Stack
The client is built with:
- React + TypeScript
- Vite for development and bundling
- Wouter for routing
- Tailwind CSS for styling
- shadcn/ui-style component primitives
- Framer Motion for motion and transitions
- React Hook Form + Zod for forms and validation

The UI covers login, registration, verification, dashboard, chat, documentation, content, and additional product surfaces.

3. Backend Stack
The server layer is built with:
- Node.js + Express 5
- TypeScript
- MongoDB + Mongoose
- Passport for JWT and Google OAuth strategies
- Zod-based request validation
- Rate limiting, CSRF protection, security headers, request context, and org context middleware

The server acts as the secure orchestration layer for auth, organizations, financial data, workflows, exports, plugins, and AI integration.

4. AI Core Stack
The AI Core is built with:
- Python
- FastAPI
- LangGraph workflow orchestration
- Provider registry and failover utilities

The AI workflow includes the following core agents:
- `master_agent`
- `income_expense_analyzer`
- `budget_planner`
- `investment_advisor`
- `debt_optimizer`
- `financial_educator`
- `master_synthesis`

5. Provider And Model Routing
The AI Core supports provider failover using configured keys. In the current local setup, the provider chain resolves as:
- gemini
- openrouter
- groq
- grok
- together

This makes the local build more resilient and better suited for experimentation and demos.

6. End-To-End Request Flow
The operational flow is:
1. The client issues a request using its API helpers.
2. The server validates auth, input, org access, and request context.
3. Financial or AI data is prepared in a normalized server-side shape.
4. The server forwards AI work to the Python AI Core.
5. The AI Core determines the analysis type, runs the relevant agents, and synthesizes the result.
6. The response returns with metadata such as provider info, agents involved, workflow trace, and tool activity.

7. Shared Contracts And Documentation
The codebase also includes shared OpenAPI definitions under `packages/contracts/openapi` and extensive reference material in `docs/`, making the project easier to understand, extend, and present.
